Resident dynamic alternating-class stress, Apple M4 Pro, 2026-08-07
======================================================================

Purpose
-------
Test the standalone one-submit grouped dynamic Metal graph against a competent
one-submit same-device generic worker in a genuinely SIMD-divergent layout. This
is a bounded stress measurement, not the canonical Kernel Phase-G path.

Provenance and regime
---------------------
Repository base: 40dee06 (detached clean worktree; stress example copied in)
Stress example SHA-256: 1f4cd03d79df435674c912589689128736a23aeffdfbcbbccb77c46cd72ec3b0
Final checked-in candidate SHA-256: 975e1c7998db4426dab3b5b6f8a2754f6ec77f97bddec672d4fadac08ec97e5e (only an added diagnostic clarifies low_arrival is sequential)
Command (twice, as independent processes):
  cargo run --release --features metal --example resident_dynamic_stress
Machine: MacBook Pro Mac16,8; Apple M4 Pro; 12 CPU / 16 GPU cores; 24 GiB
OS: macOS 26.6 build 25G5028f; Rust 1.92.0
Regime: 49,152 lanes, 16 bounded steps, WORK=512 useful dependent u64 ALU
rounds per live lane/step, cohort width 32, 3 recreated-backend batches/process,
11 samples/batch, 2 warmups/batch. Initial lanes alternate A/B and matching
break flags. Four depths (16,14,12,10) are interleaved so both classes remain
present at every asserted epoch. The generic evaluator contains both counted
bodies and uses break_if at each irrelevant loop head.

Method
------
CPU class-bucket was timed and exact-checked once per batch, before GPU warmups,
not before every GPU pair. Each primary pair receives an equal 25 ms idle
interval and alternates AB/BA order across samples/batches. Every grouped and
generic sample checks exact final frames and canonical trace against CPU; all
controls check exact final frames. Backends are recreated per batch. Two whole
benchmark invocations provide independent processes.

Reported per-call GPU times include Metal buffer/allocation work done by the
API, command encoding, submit/wait, and final readback. Evaluator source compile
is outside samples (352 us in process 1; 264 us in process 2). Submission counts
are explicit in CSV. `low_arrival_us` is the historical control name: it is
eight sequential 1/8-frame chunk submissions, not asynchronous arrivals.

Robust analysis
---------------
There is a material call-position effect, so raw paired G/U ratios compare
first and second calls unfairly. For each independent batch, compare grouped
and generic medians separately in first-call and second-call strata, then take
the geometric mean of those two ratios (lower favors grouped).

All six independent-batch robust ratios favor grouped. Median batch ratio is
0.9050 (IQR 0.8803--0.9208): grouped is 9.5% faster by this estimator. A seeded
20,000-draw bootstrap resampling each implementation within batch/call-position
gives median ratio 0.9024 and percentile 95% interval [0.8568, 0.9482]. This is
a reproducible positive for the narrow grouped-vs-competent-generic comparison.
All 66 grouped and generic samples exceed 20 ms (minimums: grouped 24.804 ms,
generic 26.082 ms), and every exact field is true.

It is NOT a full G5 closure. The 16-submit sorted/level control is faster than
the one-submit grouped median in all six batches: grouped/sorted ratios range
1.176--1.456. The one-class device null is 2.60--3.44x faster than grouped.
Grouped beats the eight sequential chunk control in all batches (G/chunk
0.820--0.944), but that control does not model real asynchronous arrival. The
standalone graph also still omits canonical Kernel Phase-G final commit.
